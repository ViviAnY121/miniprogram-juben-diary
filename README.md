# 剧本杀日历打卡 & 统计小程序

基于「微信小程序 + 云开发」搭建，用日历记录每次打本的海报、角色、DM、花费等信息，并提供年度趋势 / 剧本排行 / DM排行三种统计视图。

## 一、目录结构

```
juben-diary/
├── project.config.json          # 小程序项目配置（需要改成你自己的 AppID）
└── miniprogram/
    ├── app.js                   # 初始化云开发（需要改 CLOUD_ENV_ID）
    ├── app.json                 # 页面路由 + 底部 tabBar
    ├── app.wxss                 # 全局样式
    ├── sitemap.json
    ├── utils/
    │   ├── util.js               # 日期计算、日历格子生成、净花费公式
    │   └── cloud.js               # 云数据库/云存储的增删改查封装
    └── pages/
        ├── calendar/              # 首页：日历 + 弹窗添加
        ├── detail/                 # 记录详情：新增 / 查看 / 编辑 / 删除
        └── stats/                  # 统计：年度趋势 + 剧本排行 + DM排行（3个tab在一个页面里）
```

## 二、运行前必须做的 3 件事

1. **开通云开发**：在微信公众平台后台或开发者工具里开通「云开发」，新建一个环境，把环境 ID 复制下来，填到 `miniprogram/app.js` 里的 `CLOUD_ENV_ID`。
2. **新建数据库集合**：在云开发控制台 → 数据库，新建一个集合，名字必须是 `records`（和代码里保持一致）。权限选**「仅创建者可读写」**（这样天然就是你自己的私人数据，不用写额外的安全规则）。
3. **云存储权限**：默认的云存储权限一般已经是"仅创建者可读写"，用来存海报图片，不用额外配置；如果你在控制台改过默认规则，记得改回"仅创建者可读写"。

在 `project.config.json` 里把 `appid` 换成你自己的小程序 AppID（没有的话用开发者工具的"测试号"也能跑云开发）。

## 三、数据结构（records 集合每条记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| date | string | 'YYYY-MM-DD' |
| scriptName | string | 剧本名称 |
| character | string | 体验角色 |
| location | string | 地点 |
| dmList | array&lt;string&gt; | DM 姓名列表，支持多个（旧版本单个 dm 字段会自动兼容） |
| isPending | boolean | 是否"未定日程"，为 true 时海报黑白显示 |
| posterFileID | string | 云存储图片 fileID |
| fee | number | 剧本金额 |
| nightFee | number | 夜场费 |
| dayFee | number | 日场费 |
| hasSubsidy | boolean | 是否有补贴/倒贴 |
| subsidyAmount | number | 补贴金额，可正可负 |
| otherAmount | number | 其他金额，可正可负 |
| otherRemark | string | 其他金额的备注说明 |
| remark | string | 备注/心得 |

**总金额算法**：`总金额 = 剧本金额 + 补贴金额 + 其他金额 + 夜场费 + 日场费`（全部直接相加，补贴/其他金额自身的正负号决定是加钱还是减钱）。详情页会在保存前实时预览这个总金额。

## 四、几个我帮你做了假设的设计点（**请重点确认，不合适可以告诉我改**）

1. **"点击数字弹出添加页面"**：我做成了「日历页内的弹窗」——点格子任意位置（数字、空白，海报除外）→ 弹出一个小卡片 → 点"选择剧本海报" → 自动跳到详情页把其余信息填完，而不是先跳一个空白新页面。这样操作步骤更短。
2. **新增了"剧本名称"字段**：你的原始需求列了几项字段，但没有单独列"剧本名称"，不过日历要显示"海报"、统计要"按剧本统计"，所以我在表单里加了这一项（在体验角色前面），配图上传时一起填。
3. **一天打多本的情况**：日历格子里如果当天有多条记录，铺满显示第一张海报 + 一个"×N"的角标，点海报进最先的一条；如果你希望点了之后能选是哪一条，可以再加一个小的选择弹层。
4. **DM 多个分别统计**：一条记录可以添加多个 DM，DM 排行统计时，每个 DM 各自 +1 次打本记录，并且都按这一场的**完整总金额**计入（不是拆分平均），也就是"你和这个DM合作过几次、这几次一共花了多少钱"。如果你想要的是"总金额除以DM人数、分摊到每个DM身上"，告诉我一句话可以改，在 `pages/stats/stats.js` 的 `computeDmRanking` 里改一行。
5. **排行榜排序**：剧本/DM 排行都是"打得次数最多的排第1名"，次数相同时金额高的排前面。

## 五、剧本海报重复上传的问题

你选择了"每次手动从相册上传"。这个版本就是这么做的。如果以后打同一个本厌倦了每次都要重新传图，可以升级成"剧本库"模式（剧本名 + 默认海报存一份，选剧本名自动带出海报），这个可以作为二期功能，需要的话随时叫我加。

## 六、关于「汇文明朝体」字体（有个客观限制，请务必看一下）

汇文明朝体是一款完整的中文字体，字库文件通常有几 MB 到十几 MB，而小程序主包大小是有限制的（一般 2MB，最多可以申请到分包总共 20MB），**没办法把完整字体文件直接塞进代码包里**，所以我用的是官方推荐的运行时加载方案：

1. 你需要自己去字体来源网站下载「汇文明朝体」的 `.ttf` 或 `.otf` 文件（请确认一下这款字体的授权协议是否允许你这样嵌入到 App 里使用，商用授权和个人非商用授权条款可能不一样，我没有找到并且不会替你重新分发这个字体文件）。
2. 把字体文件上传到你云开发环境的「云存储」里（随便建个 `fonts/` 目录），上传成功后复制它的 `fileID`。
3. 打开 `miniprogram/app.js`，把 `FONT_FILE_ID` 常量填成这个 `fileID`。
4. 重新编译，小程序启动时会自动通过 `wx.loadFontFace` 下载并全局应用这个字体；如果没填、或者下载失败，会自动回退到系统默认字体，不会报错崩溃。

留意一点：`wx.loadFontFace` 本质是从一个 https 地址下载字体文件，正式发布上线后，这个云存储生成的临时链接所在域名理论上需要在小程序后台的"download 合法域名"名单里（开发者工具里可以先勾选"不校验合法域名"跳过这个检查来测试）。如果正式发布后字体加载不出来，大概率是这个域名白名单的问题，到时候可以再来找我一起排查。

## 七、图表说明

年度趋势图是用 Canvas 2D 手写的双 Y 轴折线图（左轴=次数，紫色；右轴=金额，橙色），没有引入任何第三方图表库，`wx-charts` 之类的都没用到，纯原生实现，样式比较朴素，能用但谈不上精美，后面想美化随时可以加动画、渐变、Tooltip 等。

## 八、常见问题排查

- **日历页提示"加载失败，请检查云开发配置"**：一般是 `CLOUD_ENV_ID` 没改、或者 `records` 集合没建、或者集合权限设置不对。
- **添加记录后日历没刷新**：`onShow` 里已经会自动重新拉取当前月份数据，从详情页返回日历页应该会自动刷新；如果没刷新，检查一下 `navigateBack` 是否真的执行了。
- **统计页图表画不出来**：Canvas 2D 需要基础库 2.9.0 以上，检查开发者工具左上角的"详情-本地设置-调试基础库"版本。
